# 01 - Docker 镜像 CI/CD 方案 - 2026-07-25

## 背景

本项目 fork 自 `Gyyyn/OpenWebTTS`，托管于 `XduDSJ/OpenWebTTS`。原项目支持 Docker 部署（含 `Dockerfile` 与 `compose.yaml`），但无 CI/CD 流水线。本次新增 GitHub Actions 工作流，自动构建 Docker 镜像并发布到 GitHub Container Registry（ghcr.io），便于直接 `docker pull` 使用，无需本地构建。

## 方案设计

| 维度 | 选择 | 说明 |
|------|------|------|
| 触发时机 | push master + 打 v* tag + 手动 | master 推送产出 latest；tag 产出语义化版本 |
| 目标架构 | linux/amd64 | 单架构，构建快（约 10-20 分钟） |
| 镜像仓库 | ghcr.io | GitHub 原生托管，权限用内置 `GITHUB_TOKEN` |
| 镜像名 | `ghcr.io/xdudsj/openwebtts` | owner/镜像名自动小写化 |
| 构建缓存 | GitHub Actions cache (`type=gha`) | 加速后续构建 |

### 镜像标签策略

| 触发 | 产出标签 |
|------|----------|
| push master | `latest`、`sha-xxxxxxx` |
| push v1.2.3 | `1.2.3`、`1.2`、`1`、`sha-xxxxxxx` |

- `latest` 仅在默认分支（master）推送时更新，tag 不覆盖 latest。
- `sha-xxxxxxx` 为 commit 短哈希，便于回溯任意构建。

## 改动文件清单

| 文件 | 类型 | 说明 |
|------|------|------|
| `Dockerfile` | 修改 | 补 `npm install`（原缺失导致构建失败），优化分层缓存，apt 列表加 `curl`（HEALTHCHECK 依赖） |
| `.dockerignore` | 新增 | 排除 .git/node_modules/文档/运行时数据，加速构建 |
| `.github/workflows/docker-publish.yml` | 新增 | CI/CD 工作流 |
| `compose.yaml` | 修改 | 默认拉取 CI 镜像（`image:`），保留 `build:` 注释供本地构建切换；新增 volumes 挂载模型与用户数据 |

## Dockerfile 修复说明

原 Dockerfile 在 `COPY . .` 后直接 `RUN npm run build`，但**缺少 `npm install`**。由于 `node_modules/` 与构建产物均在 `.gitignore` 中（CI 干净 checkout 不含 node_modules），原写法在 CI 中必然失败。

修复方式（利用分层缓存，源码变动不触发重装依赖）：

```dockerfile
# 先单独复制 package.json 以利用分层缓存
COPY package.json ./
RUN npm install

COPY . .
RUN npm run build
```

## 使用方法

### 拉取镜像

```bash
# 最新（master）
docker pull ghcr.io/xdudsj/openwebtts:latest

# 指定版本
docker pull ghcr.io/xdudsj/openwebtts:1.2.3
```

### 运行

```bash
docker run -d -p 8000:8000 \
  -v $(pwd)/models:/app/models \
  -v $(pwd)/users:/app/users \
  ghcr.io/xdudsj/openwebtts:latest
```

或使用 `compose.yaml`（已默认拉取 CI 镜像，并挂载 models/users 持久化数据）：

```bash
docker compose up -d
```

> 若需本地构建而非拉取镜像，编辑 `compose.yaml`：注释 `image:` 行，启用 `build: .` 行。

### 手动触发

GitHub 仓库 → Actions → "构建并发布 Docker 镜像" → Run workflow。

## 首次使用前置步骤

1. **镜像可见性**：首次推送后，镜像默认继承仓库可见性。前往 `https://github.com/users/XduDSJ/packages/container/openwebtts/settings` 可调整为 public/private。
2. **无需额外 Token**：工作流使用内置 `GITHUB_TOKEN`，无需手动创建 secret。

## 注意事项

1. **构建耗时**：`requirements.txt` 含 `openai-whisper`（依赖 PyTorch）、`coqui-tts`、`piper-tts` 等，镜像体积约 5-10GB，首次构建 15-30 分钟。后续命中缓存会快很多。
2. **GHA 缓存上限 10GB**：本项目依赖层较大，若缓存超限会被淘汰。如遇缓存失效频繁，可改用 `type=registry` 缓存（推到 ghcr.io 专用缓存层）。
3. **数据持久化**：`compose.yaml` 已挂载 `./models` 与 `./users` 到容器，容器重建后模型与用户数据不丢失。`docker run` 方式需手动加 `-v` 参数。
