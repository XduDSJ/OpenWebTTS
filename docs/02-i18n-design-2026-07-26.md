# OpenWebTTS 中英文国际化（i18n）设计

- 日期：2026-07-26
- 状态：已实现（2026-07-26，Tasks 1-8 完成，静态验证通过）
- 作者：brainstorming 流程产出

## 1. 目标

为 OpenWebTTS 前端增加中英文双语支持，用户可切换语言，选择后持久化。覆盖全部 UI 文本（HTML 静态文本 + JS 动态文本）。

## 2. 已确认决策

| 决策项 | 选择 |
|--------|------|
| 翻译范围 | 全部 UI 文本（HTML 静态 + JS 动态） |
| 持久化方式 | 浏览器 localStorage |
| 默认语言策略 | 自动检测浏览器语言（navigator.language） |
| 翻译机制 | data-i18n 属性 + t() 函数 + 单文件翻译表（零依赖、零构建） |

## 3. 架构概览

新增独立 i18n 模块，零依赖、零构建，与现有预构建静态文件兼容：

```
static/
  locales/
    en.json      ← 英文翻译表（~200 key）
    zh.json      ← 中文翻译表（~200 key）
  js/
    i18n.js      ← i18n 模块（加载、切换、应用翻译）
```

**数据流**：页面加载 → `i18n.js` 检测语言（localStorage > navigator.language > 'en'）→ fetch 对应 JSON → 遍历 DOM 替换 `data-i18n` 元素文本 → JS 代码通过 `t('key')` 获取动态文本。用户切换语言 → 存 localStorage → 重新应用翻译（无需刷新页面）。

## 4. 翻译表格式与 key 命名

扁平 key + 点分命名空间，按页面/功能分区：

```json
{
  "nav.new_book": "New Book",
  "nav.library": "Library",
  "nav.config": "Config",
  "nav.commands": "Commands",
  "login.placeholder_username": "Username or Email",
  "login.placeholder_password": "Password",
  "login.sign_in": "Sign in",
  "toast.book_saved": "Book saved successfully",
  "error.load_failed": "Failed to load",
  "player.listen": "Listen",
  "player.pause": "Pause",
  "player.play": "Play"
}
```

命名空间约定：
- `nav.` — 导航栏（New Book / Library / Config / Commands）
- `login.` — 登录相关（用户名、密码、登录/登出、状态）
- `toast.` — 临时提示消息
- `error.` — 错误消息
- `player.` — 播放器控件
- `book.` — 书籍操作（导入、保存、删除等）
- `config.` — 配置页文本
- `common.` — 通用文本（Cancel / Confirm / Loading 等）

扁平结构而非嵌套对象——查找简单，`t('nav.new_book')` 一次属性访问。

## 5. HTML 集成

用三种 `data-*` 属性标记可翻译元素：

```html
<!-- 文本内容 -->
<span data-i18n="nav.new_book">New Book</span>

<!-- placeholder -->
<input data-i18n-placeholder="login.placeholder_username" placeholder="Username or Email">

<!-- aria-label（无障碍） -->
<button data-i18n-aria-label="player.listen" aria-label="Listen to current book">
```

`applyTranslations()` 遍历这三类属性，分别设置 `textContent`、`placeholder`、`aria-label`。HTML 里保留英文原文作为默认值——即使翻译加载失败，页面仍可读。

涉及文件：
- `templates/index.html`（401 行，~100+ 处文本）
- `templates/config.html`（306 行）

## 6. JS 集成

`i18n.js` 暴露的接口：

| 函数 | 作用 |
|------|------|
| `async initI18n()` | 页面加载时调用：检测语言 → fetch JSON → applyTranslations → 设置 `<html lang>`。返回 Promise，resolve 后翻译可用 |
| `t(key)` | 返回当前语言的翻译字符串，缺失时回退到英文，再回退到 key 本身。同步函数（翻译表已加载后调用） |
| `async setLang(lang)` | 切换语言：存 localStorage → 加载翻译 → 重新 applyTranslations → 更新 `<html lang>`。返回 Promise |
| `getCurrentLang()` | 返回当前语言代码 `'en'` / `'zh'`。同步函数 |

JS 中所有硬编码英文替换为 `t('key')`：

```javascript
// 之前
textContent = 'Not signed in';
// 之后
textContent = t('login.not_signed_in');
```

涉及文件及预估改动量：
- `static/js/index.js`（~68 处）
- `static/js/config.js`（~15 处）
- `static/js/helpers.js`（~6 处）
- `static/js/UI.js`（~5 处）

## 7. 语言切换器 UI

在现有顶栏（Account / Notifications 旁边）加语言切换控件，与现有 Tailwind 风格一致。切换后即时生效（`setLang()` 重新应用翻译，不刷新页面）。

采用**下拉菜单**形式：点击展开「中文 / English」两项，当前语言打勾。下拉菜单比图标切换更直观，用户一眼看到可选语言，符合常见 i18n 切换器惯例。

## 8. 语言检测优先级

```
1. localStorage('openwebtts_lang')  ← 用户明确选择过
2. navigator.language               ← 浏览器语言，'zh' 开头 → 'zh'，否则 → 'en'
3. 'en'                             ← 兜底默认
```

`<html lang="zh">` 或 `<html lang="en">` 动态更新，确保屏幕阅读器和搜索引擎正确识别。

## 9. 错误处理与回退

| 场景 | 行为 |
|------|------|
| JSON fetch 失败 | 回退到英文（HTML 原文仍在），console.warn 提示 |
| 当前语言缺失某 key | 回退到英文值 |
| 英文也缺失 | 返回 key 字符串本身（开发期可见，提示漏翻） |
| 翻译未加载完成时调用 `t()` | 返回 key 本身，翻译加载后 DOM 重新应用 |

## 10. 测试验证

- **切换测试**：在 index 和 config 两个页面切换语言，验证所有可见文本（按钮、标题、placeholder、aria-label）即时变化
- **持久化测试**：切换语言后刷新页面，验证语言保持
- **检测测试**：清除 localStorage，模拟 `navigator.language='zh-CN'`，验证首次显示中文
- **回退测试**：从 zh.json 删除一个 key，验证该处显示英文；删除英文也删除，验证显示 key 名
- **JS 动态文本测试**：触发 toast 提示、错误消息，验证按当前语言显示

## 11. 不在范围内（YAGNI）

- 不做后端 i18n（API 错误消息、日志等保持英文）
- 不做更多语言（仅 zh/en，未来需要时再加文件即可）
- 不做翻译表分片（2 页面 ~200 key，单文件足够）
- 不做翻译管理后台（JSON 文件手动维护）
