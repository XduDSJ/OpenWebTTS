## 背景

i18n 改动将大量硬编码字符串替换为 `t()` 调用，同时引入了 `appState` 全局状态对象（`elements` 存 DOM 引用，`variables` 存状态变量）。改动过程中遗漏了部分变量的 `appState.` 前缀，导致运行时 `ReferenceError`；另有一处 `e.preventDefault()` 误加，阻止了文件选择器和 checkbox 的默认行为。

### 2. 文件选择器 / checkbox 无反应

**根因**：`index.js:2398` document click 监听器（用于点击外部关闭下拉菜单）中误加 `e.preventDefault()`，阻止了文件选择器打开和 checkbox 切换的默认行为。

**修复**（commit 3cb3d73）：删除该行。该监听器只需关闭菜单，不需要 preventDefault；下拉菜单内部点击有 `stopPropagation` 不会冒泡到 document。

### 3. podcast.js 错误处理 body 二次消费（严重）

**根因**：commit 3cb3d73 改进错误处理时用了 `response.json()` + fallback `response.text()` 的模式。但 Fetch 规范中 `json()` 内部先 `consume body` 读取整个 stream 并将 body 置为 null，再 `JSON.parse`。当响应非 JSON（如后端返回 HTML 错误页）时：
1. `json()` 消费 body 成功 → JSON 解析失败 → 抛 SyntaxError
2. catch 中 `text()` 发现 body 已消费 → 抛 `TypeError: body stream already read`
3. TypeError 逃逸，跳过 `throw new Error(errorMsg)`
4. 外层 catch 捕获 → 返回 `{ success: false, error: "body stream already read" }`

**结果**：修复初衷（暴露真实 HTTP 状态码）在非 JSON 场景下完全落空。

**修复**（本次）：改为先 `text()` 再 `JSON.parse()`，body 只读一次：
```javascript
if (!response.ok) {
    const responseText = await response.text();  // 只读一次
    let errorMsg = `Failed to generate podcast (HTTP ${response.status})`;
    try {
        const errorData = JSON.parse(responseText);
        errorMsg = errorData.detail || errorMsg;
    } catch (e) {
        console.error('Non-JSON error response:', responseText);
    }
    throw new Error(errorMsg);
}
```

**发现方式**：Oracle 代码审查（ses_0614fc8a9ffear4F1SwTGN8lh1）指出。
